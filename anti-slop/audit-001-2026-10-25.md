# Audit 001 - Finote Light Theme

Scope: Light theme only, using current `main` source and supplied design audit. No source code changed during this audit.

## Findings

1. **LOW - Separate brighter semantic accents are below AA if used for text.** The light `incomeAccentColor #00896C` is 4.38:1 on white, and `expenseAccentColor #C5685A` is 3.82:1. Current Dashboard passes these only as icon colors; amount text uses darker `incomeColor #007A60` and `expenseColor #A84F43`, which exceed 4.5:1 on white. Keep accents icon-only or darken before any text usage.

2. **MEDIUM - Light palette has weak separation between page and card surfaces.** `surface #F8FAF9` and `surfaceContainerLow #FFFFFF` yield only 1.05:1 contrast. Dashboard and other card-heavy screens can read as one white plane, weakening grouping and visual hierarchy. Consider a slightly stronger pale mint canvas or a lightly tinted card distinction, then verify key screens.

3. **MEDIUM - Current Light palette differs from the previously reviewed design direction.** `main` now uses surface `#F8FAF9` and primary `#0D766A`; earlier approved redesign work used mint surface `#E8F1EC` and brighter teal `#00A985`. Latest `main` is source of truth, but decide whether the restrained palette is intentional or whether the stronger mint direction should be restored.

4. **LOW - Light theme block is inconsistently formatted.** `_lightScheme` indentation and blank lines differ from surrounding Dart style. `dart format` on `app_theme.dart` would normalize without behavioral change.

5. **LOW - Theme-specific styling is uneven across Material controls.** Text and outlined buttons set explicit light teal foregrounds, while other controls mostly inherit ColorScheme. Visually check filled, disabled, focused, and pressed states before changing defaults broadly.

6. **LOW - Runtime evidence is missing.** Widget tests cover selected Dashboard widths and text scaling, but actual Android appearance, screen-reader traversal, and full 200% system text are not recorded. Device inspection should follow any selected fixes.

## Suggested order

- Resolve palette intent from item 5.
- Verify contrast pairs and usages in item 2.
- Inspect Light Dashboard and Settings in app at normal and enlarged text; decide surface hierarchy based on visible evidence (item 4).
- Apply only selected findings, keep changes in theme/UI files, run targeted tests and analyze touched files.

No findings were fixed in this audit. User selects which finding numbers to address before any edits.
